# 规则集规范（给外部协作者 / AI 助手）

这份文档描述 PromptSmith 的**规则集（ruleset）**格式。按这份规范产出的目录，程序可直接加载，无需改代码。

> **最重要的一句话：输出契约必须出现在入口正文（system.md）的前 2,000 字内。**
> 模型对前缀的遵循度远高于后文。把契约放到后面 = 格式必然崩。

---

## 一、目录结构

一套规则集是一个目录，最小可用形态：

```
my-ruleset\
├── profile.json     必需。字段定义、预算、校验规则
├── system.md        必需（或用 resident_blocks 替代）。入口正文
├── kb\              必需。可检索的知识块，每个 .md 一块
│   ├── 01-xxx.md
│   └── 02-yyy.md
├── index.json       推荐。块索引（缺则自动扫描生成）
└── aliases.json     可选。口语 → 块 id 的映射
```

程序也接受另外两种形态（无 `profile.json` 时自动推断）：

| 形态 | 目录长什么样 |
|---|---|
| 现成技能 | `SKILL.md` + `references/` |
| 纯块目录 | 一堆 `*.md`，无入口 |

但**要做到质量可控，请用完整形态**并显式写 `profile.json`。

## 二、profile.json

```json
{
  "id": "my-ruleset",
  "display_name": "显示名 · 用于目标模型",
  "target_model": "目标模型名",
  "target_kind": "image",
  "output_format": "fields",
  "rules_file": "system.md",
  "kb_dir": "kb",
  "entry_mode": "full",
  "resident_blocks": [],
  "fields": [
    { "key": "q", "label": "质量", "required": true }
  ],
  "budget": {
    "default_chunks": 6,
    "min_chunks": 2,
    "max_chunks": 8,
    "max_inject_chars": 15000,
    "hard_ceiling_chars": 24000,
    "token_ratio": 0.7,
    "safety_tokens": 2000,
    "alias_max": 500
  },
  "select": {
    "mode": "A",
    "keyword_weight": 0.65,
    "alias_weight": 0.25,
    "vector_weight": 0.35
  },
  "generate": {
    "temperature": 0.7,
    "top_p": 0.8,
    "max_output_tokens": 4096,
    "enable_thinking": false
  },
  "validate": {
    "must_start_with": "q",
    "ban_light_words": [],
    "unique_fields": []
  }
}
```

### 字段说明

| 字段 | 必需 | 作用 | 取值 |
|---|---|---|---|
| `id` | 是 | 唯一标识，界面下拉框用它 | 建议小写连字符 |
| `display_name` | 否 | 界面显示名 | 任意 |
| `target_model` | 否 | 目标模型说明，仅显示 | 任意 |
| `target_kind` | 否 | `image` / `video` / `text` | 影响 `x` 字段语义 |
| **`output_format`** | **是** | 决定校验方式 | `fields` / `oneline` / `paragraph` / `auto` |
| **`rules_file`** | 二选一 | 入口正文文件名 | 通常是 `"system.md"` |
| **`resident_blocks`** | 二选一 | 用哪几个块拼入口（`rules_file` 为 `null` 时生效） | 块 id 数组，如 `["k003","k017"]` |
| `kb_dir` | 否 | 块目录，默认整个规则集目录 | `"kb"` |
| `entry_mode` | 否 | 默认入口档位 | `full` / `slim` / `core` |
| `fields` | `fields` 模式必需 | 输出字段定义 | 见下 |
| `budget` | 否 | 取块预算 | 见下 |
| `select` | 否 | 检索权重 | 见下 |
| `generate` | 否 | 采样参数 | 见下 |
| `validate` | 否 | 校验规则 | 见下 |

### `output_format` 四种模式

| 值 | 期望输出 | 校验行为 |
|---|---|---|
| `fields` | `q: xxx` 逐行字段 | 字段必须齐 + 禁词 + 首行顺序 |
| `oneline` | 单行 tag 串 | 不查字段，只查长度和禁词 |
| `paragraph` | 自然语言段落 | 不查字段，查长度区间 |
| `auto` | 任意 | **不校验结构**，只查空/禁词/长度 |

> 若你的规则集格式不属于以上任何一种，用 `auto` + `validate.regex` / `validate.require_keys` 自定义。

### `fields` 定义

```json
"fields": [
  { "key": "q",  "label": "质量",     "required": true, "fixed": "" },
  { "key": "nh", "label": "手部负面", "required": true,
    "fixed": "bad hands, extra fingers, missing fingers" }
]
```

| 键 | 作用 |
|---|---|
| `key` | 字段标识，必须与模型输出行首一致（1–3 个字母） |
| `label` | 界面显示名 |
| `required` | 是否必须出现 |
| `fixed` | 若设置，该字段内容由程序写死，模型不必生成 |

**字段顺序即输出顺序。** 第一个字段决定 `must_start_with` 的默认值。

### `budget`

| 键 | 作用 | 建议 |
|---|---|---|
| `default_chunks` | 自动取几块 | 小语料 4–6，大语料 6–8 |
| `min_chunks` / `max_chunks` | 取块数量上下限 | 2 / 8 |
| `max_inject_chars` | 注入块的总字数上限 | 语料大块多时调低 |
| `hard_ceiling_chars` | 手动选块的硬顶，超了拒绝生成 | 约为上一项的 1.6 倍 |
| `block_max_chars` | 单块字数上限（默认 1500） | 有「原子块」时调大，见 §四 |
| `token_ratio` | 中文字数 → token 的估算比 | 0.7 |
| `safety_tokens` | 预留余量 | 2000 |
| `alias_max` | 自动学习别名的总量上限 | 300–500 |

### `validate`

| 键 | 作用 |
|---|---|
| `must_start_with` | 第一行必须是哪个字段（写 `字段名` 或 `字段名:` 都行，末尾冒号自动剥） |
| `ban_light_words` | 禁止出现的词（大小写不敏感，子串匹配） |
| `unique_fields` | 这些字段内不允许重复 tag |
| `regex` | 全文必须匹配的正则 |
| `require_keys` | 必须包含的 JSON 键（自动剥 ```` ``` ```` 代码块） |
| `min_chars` / `max_chars` | 去空白后的字数区间 |

**字段名不限长度**：`q` / `a` 这种短 tag 和 `subject_definitions` / `detailed_description` 这种长蛇形名都受支持（`^[a-z][a-z0-9_]{0,39}$`）。只有一点必须一致——`fields` 里写的名字要跟模型实际输出的行首完全相同。

## 三、system.md（入口正文）

这是**每次请求都全量发送**的部分，直接决定输出格式是否稳定。

### 硬性要求

1. **长度 8,000–13,000 字，绝不能超过 15,000 字**
2. **必须包含**（按此顺序）：
   - 角色定位（一句话）
   - **输出契约**（字段清单 + 每行格式 + 禁止事项）← 必须在 2,000 字内
   - 各字段职责表（放什么 / 不放什么）
   - 常见错误清单
   - 默认值（用户没提时补什么）
   - 路由说明（什么需求该参考哪类块）
3. **不要**用 YAML frontmatter（那是别的工具的格式）
4. **不要**出现「安全 / 免责 / 仅限 / 拒绝 / 成年人」这类措辞——实测会让本地小模型在正文前加免责声明，直接破坏输出格式

### 结构模板

```markdown
# <规则集名称>

## 你的角色
你是 <角色>。用户给 <输入形态>，你直接输出 <输出形态>。

## 输出契约（硬性）
严格按以下 N 个字段逐行输出：

<字段清单>

规则：
- 全小写英文 / 中文（按需）
- 逗号加空格分隔
- N 个字段一个都不许省
- 第一行必须是 <字段>
- 不解释、不评价、不复述需求、不加任何说明
- 不要用代码块包裹
- <其他禁止事项>

## 各字段的职责
<表格：字段 | 放什么 | 不放什么>

## 常见错误（务必避免）
1. ...

## 默认值
<用户没提时补什么>

## 该参考哪类块
<需求类型 → 块标题前缀>
```

### 如果不想写 system.md

用 `resident_blocks` 指定几块作为入口：

```json
"rules_file": null,
"resident_blocks": ["k001", "k004", "k012"]
```

程序会按顺序拼接这些块的**原文**作为入口。适合"入口内容本身就在块里"的情况。

⚠️ 但要注意：拼接后的总长度仍受上下文预算约束，且**契约必须在最前面那个块里**。

## 四、kb/（知识块）

### 切块标准

| 项 | 要求 |
|---|---|
| 单块字数 | **300–1,500 字**（超出请继续按下级标题切；不足请合并到相邻块） |
| 文件名 | `{两位组号}-{块标题}.md`，去掉 `: \ / * ? " < > \|` |
| 首行 | `# {块标题}`（程序用它做标题） |
| 第二行 | `> 来源：<原始文件> §<章节>`（可选，便于溯源） |
| 编码 | UTF-8，无 BOM |

### 切分依据

按 `#` / `##` / `###` 标题切。**不要按固定字数硬切**——那会把一个完整规则切成两半。

### 原子块：拆开就废的东西不要拆

有一类内容天然不可分割——**一份完整可粘贴的成品样例**（整段 prompt、整份字段输出）。
把它切成 1,500 字一段，每一段单独喂给模型都是废的。

这类块允许超出常规上限，但要两步都做：

1. 在 `profile.json` 里声明上限，例如 `"budget": { "block_max_chars": 6000 }`
2. 块标题带前缀标明性质，例如 `样例-第一人称-传教士`、`待验证-跪地口交`，让人一眼知道这是成品而不是规则

代价是占用预算多（一个 2,800 字的样例就吃掉 1/4 默认注入量），所以**原子块不要超过语料的 1/3**。

### 标题要好检索

这是最容易做错的地方。反例：

```
Semantic Addition Gate（第二版收口 · 通用优化权限）     ← 检索不到"逆光"
第二版 · Instruction ≠ Prompt Content（A1 硬规则）      ← 检索不到"负面词"
```

正例：

```
01-质量与画质 tag 基础
02-镜头与构图
03-光线白名单
04-负面提示词基础
```

**判据：用户会用什么样的中文词来描述这个需求？把这些词放进标题。**

## 五、index.json

```json
{
  "blocks": [
    {
      "id": "k001",
      "title": "质量与画质 tag 基础",
      "file": "kb/01-质量与画质 tag 基础.md",
      "chars": 362,
      "keywords": ["质量", "masterpiece", "highres"],
      "aliases": [],
      "src": "kb/01-质量与画质 tag 基础.md",
      "hash": "可选，用于向量增量更新"
    }
  ]
}
```

| 键 | 说明 |
|---|---|
| `id` | 唯一。建议 `k001` 递增 |
| `title` | 与文件首行 `#` 标题一致 |
| `file` | **相对规则集目录的路径**，用 `/` 分隔 |
| `chars` | 去空白后的字数 |
| `keywords` | **必须是从该块正文里真实出现的词**，5–8 个，别编 |

若不给 `index.json`，程序会现场扫描 kb 生成（质量稍差，但可用）。

## 六、aliases.json

口语说法 → 块 id。**只在检索打分时读进内存，不进提示词，不占上下文。**

```json
{
  "map": {
    "逆光": ["k003"],
    "打光": ["k003"],
    "两个人": ["k005"],
    "双人": ["k005"]
  }
}
```

- 键：用户可能说的词（2–4 字最佳）
- 值：块 id 数组（一个词可指向多块，取前 8 个）
- **优先级高于** `data/zh2tag.json`（全局中英词表）

> 程序会自动学习：你手动选块并生成后，输入里的有效词会被记进这个文件的 `map`。
> 只记 2–4 字、非停用词、且能在块标题或词表里对得上的词。

## 七、验收标准

改完必须跑这两步，光"看起来对"不算：

### 1. 结构化校验

```bash
python src/verify_ruleset.py <规则集目录>
```

检查：profile 必需键、fields 与 output_format 是否自洽、system.md 长度、kb 命名与字数、index 一致性、aliases 悬空引用。

### 2. 加载与检索

```bash
python src/promptsmith.py <规则集id> "<一句用户会说的话>"
```

应看到：块数、入口字数、检索命中的前 8 块及命中词。
**如果命中的块和你预期的完全不相关，说明标题写得不好，回去改标题。**

## 八、六个已踩过的坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 契约放太后 | 用精简入口后模型只吐 tag、不按格式 | 契约必须在前 2,000 字 |
| 用块拼接做入口 | 接口丢了（契约在 system.md 里，不在块里） | 入口从 system.md 截，不从块拼 |
| 枚举禁词 | 禁 `warm light` → 模型写 `warm lighting` | 改成"凡是自造光影形容词一律禁止"这类通则 |
| 条件规则 | "逆光时才加保底" → 漏掉 1/3 情况 | 改成固定模板，让它照抄 |
| 全词匹配 | 用户说「逆光构图」，块标题只有「光线白名单」→ 匹配不上 | 中文必须用 2/3/4 字 n-gram 拆 |
| 写安全措辞 | 描述里出现「仅限成年人」→ 模型在正文前加免责声明 | 一个这类词都别写 |
